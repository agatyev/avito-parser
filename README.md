# avito-parser

Раз в час заходит на выдачу Avito по вашей ссылке и присылает письмом объявления,
которых вы ещё не видели.

## Запуск

```bash
cp .env.example .env     # вписать SMTP и адреса
docker compose up -d --build
```

Страница управления: http://127.0.0.1:8080 — доступна только с этой машины.
Вставьте туда ссылку на выдачу Avito с выставленными фильтрами (вид «Списком»,
не «На карте»). Остальное сервис делает сам.

Всё состояние — в `data/avito.db`: поиски, найденные объявления, адреса рассылки
и подписки. Письмо не ушло — строка в `seen` остаётся с `sent = 0` и уйдёт
следующим заходом **из базы**, даже если объявление уже исчезло с Avito.

Обход страниц останавливается на первой странице, где встретилась уже известная
карточка. Обычно это первая же страница, то есть один заход в час. Если за час
появилось больше одной страницы — сервис сам пойдёт глубже, до `max_pages`.

## Подписки

Каждый адрес подписан на свои поиски. На странице под адресом видны все поиски:
нажатием включаете и выключаете письма по каждому из них. Новый поиск уходит на
все адреса, новый адрес получает все поиски — дальше выключаете лишнее. Так
«мини пк» может приходить на рабочую почту, а «мини пк» и «дачи» — на свою.

Письмо по поиску уходит одно, сразу всем подписанным. Если на поиск не подписан
никто, находки остаются в очереди и уйдут, как только адрес появится.

## Настройки

`config.yaml` — период, глубина, порт. `.env` — почта:

| Переменная | Что это |
|---|---|
| `SMTP_HOST`, `SMTP_PORT` | сервер почты; порт 465 — SSL, иначе STARTTLS |
| `SMTP_USER`, `SMTP_PASS` | логин; для Gmail нужен пароль приложения |
| `MAIL_FROM` | адрес отправителя, обычно равен `SMTP_USER` |
| `MAIL_TO` | адреса для первого запуска, через запятую; дальше рассылка правится на странице |
