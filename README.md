# avito-parser

Раз в час заходит на выдачу Avito по вашей ссылке и присылает письмом объявления,
которых вы ещё не видели.

## Запуск

```bash
cp .env.example .env     # вписать SMTP и адреса
docker compose up -d --build
```

Страница управления: http://127.0.0.1:8080 — доступна только с этой машины.
Вставьте туда ссылку на выдачу Avito с выставленными фильтрами (вид «Списком»,
не «На карте»). Остальное сервис делает сам.

## Как это работает

```
раз в час, по очереди для каждой ссылки:
  Camoufox (headless Firefox) → главная Avito → страницы выдачи с ?s=104
  разбор карточек по data-marker
  запись в seen: новые строки получают sent = 0
  письмо со всеми строками, где sent = 0 → при успехе sent = 1
```

Всё состояние — одна таблица `seen` в `data/avito.db`. Письмо не ушло — строка
остаётся с `sent = 0` и уйдёт следующим заходом **из базы**, даже если объявление
уже исчезло с Avito. Падение сервиса в любой момент не теряет объявления; худшее,
что может случиться — один дубль письма, если процесс умрёт между отправкой и
отметкой.

Обход страниц останавливается на первой странице, где встретилась уже известная
карточка. Обычно это первая же страница, то есть один заход в час. Если за час
налило больше одной страницы новья — сервис сам пойдёт глубже, до `max_pages`.

## Настройки

`config.yaml` — период, глубина, порт. `.env` — почта:

| Переменная | Что это |
|---|---|
| `SMTP_HOST`, `SMTP_PORT` | сервер почты; порт 465 — SSL, иначе STARTTLS |
| `SMTP_USER`, `SMTP_PASS` | логин; для Gmail нужен пароль приложения |
| `MAIL_FROM` | адрес отправителя, обычно равен `SMTP_USER` |
| `MAIL_TO` | получатели через запятую; с страницы правятся в `data/mail.json` |

## Разработка

```bash
pip install -e ".[dev]"
ruff check .
pytest
```

`data/html/<id>.html` — снимок последней выдачи по каждой ссылке; с него начинают
разбираться, когда Avito меняет вёрстку.
